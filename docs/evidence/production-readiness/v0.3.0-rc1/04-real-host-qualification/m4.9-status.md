## 3. Residual risk / not claimed (consolidated)

Consolidated from the eight milestone docs' residual sections plus the open
issues above. Nothing here is a surprise: each item is disclosed in the
milestone that found it, with its evidence.

**Infrastructure-provability boundaries (single shared host):**

- **Host reboot is not provable** — the qualification host is itself a
  disposable KVM guest; the four-daemon cold-restart + cold-reconcile leg
  (M4.3 Leg E, re-exercised by M4.7's F1) is the labeled subset.
- **Lifecycle evidence is single-VM, single-node, serial** (M4.3): one
  operation at a time; concurrency evidence is limited to M4.8's bounded
  read/write workload, not concurrent lifecycle operations.
- **Cross-restart snapshot lifecycle edge** (M4.5, #376 side effect):
  snapshot/clone handles taken before a stord restart are not rehydrated
  across the restart boundary — recorded with the storage residuals.
- **Multi-host anything is unprovable** (declaration §5): multi-host
  migration, stretched-L2/VXLAN fabric, multi-node network semantics.
  Capability is capped at **KVM-VERIFIED**; the nwd fabric provider fails
  closed in the qual config (prompt-04's network evidence is the local-bridge
  topology + the host-safety gate).
- **Nested virtualization only**: all guest virtualization ran through
  `/dev/kvm` inside a KVM guest; bare-metal KVM behavior is not separately
  evidenced. Timing margins carry nested-virt slack.
- **All M4.8 numbers are baselines on this host** (16 vCPU / 31 GiB, itself
  resized from the 4 vCPU / 7.8 GiB recorded at M4.1) — no concurrency,
  density, throughput, or requests-per-second claim may be derived from them.

**Open disclosed issues (the 14 from §2), worst-first:**

- **#394** — concurrent-write migration silently loses data (dirty bitmap
  sees only stord-mediated writes; no post-pause final sweep). Quiescent-
  volume migration is the claimed mode; the specs record it (#398/#403).
- **#368** — a genuinely transient effector failure terminally fails a
  journaled VM create and nothing re-drives it (four trigger directions
  recorded: nwd, stord, agent, CP-side shapes). Disclosed, not gated, in
  M4.7; recovery paths (cleanup-delete, retry) are proven.
- **#345's CH-side root** — the v43 control-loop hang after guest poweroff
  is contained (stop verifies liveness, SIGKILLs a survivor), not cured.
  Together with the **CH v43 serial-console upstream defect** (the recorded
  gate above KVM-VERIFIED; #409/#410 is machinery-side remediation of one
  manifestation, thread-name-coupled to v43 and re-verification is required
  at any CH upgrade), this bounds the VMM-pinning claim.
- **#355 (UI half)** — the UI firewall editor writes a dead-end store in its
  own dialect; UI-authored rules never reach a node. Plus **#360** (legacy
  call sites can apply empty rulesets) and the pre-fix-stored-data caveats
  (pre-#365 NULL gateways, pre-#369 dialect rules — re-save repairs).
- **#378 / #379** — snapshot/clone accepted-then-fails-closed on
  core-managed nodes (UX gap); LVM unreachable from the VM lifecycle.
- **#384 / #385 / #386** — last-writer-wins physical upserts + clone TOCTOU;
  respawned stord drops operator config beyond the allowlist; ownerless
  imported/template volumes.
- **#401 / #402** — destination-only stord not expressible; mTLS rejection
  observability.
- **#351 / #336 / #372** — delete-path kill-refusal tolerance;
  JWT-secret/encryption-key coupling; the remaining chvctl↔BFF deferred
  contract-drift subset.

**Inherited / design non-claims (unchanged):**

- **M2.5 delete retention**: `vm delete` removes authority-side state but the

  warned, never gated, per the M2.5 scope decision; re-observed in
  M4.3/M4.5/M4.7/M4.8.

  core-managed mode by design (single-writer enforcement) — M4.6/M4.7 drive
