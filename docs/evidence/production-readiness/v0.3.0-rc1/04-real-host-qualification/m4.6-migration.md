## 1. Scope

The prompt-04 milestone §M4.6: single-host two-stord disk migration over mandatory
mTLS, positive and negative identity cases, every negative leg asserting fail-closed
behavior — driven directly at the stord gRPC surface (grpcurl over each daemon's UDS;
the node daemons serve no reflection, so the scenario uses
`-import-path/-proto` with the M2.5-RC4-proven `unix://` invocation).

**Claimed:**
- The positive contract: seeded volume → `TriggerDiskMigration` → BULK_COPY →
  iterative dirty-sync rounds → `PAUSED_FINAL_SYNC` (needs_vm_pause=true) →
  `ResumeDiskMigration{vm_paused:true}` → COMPLETED → destination byte-identical to
  the source (harness-level SHA-256 + `cmp`).
- mTLS is mandatory and total: no configuration path reaches a plaintext migration
  channel (N1 + N8), every identity mismatch fails closed at or before the TLS
  handshake with zero bytes leaving the source (N2/N3/N4/N7), structurally invalid
  identity material prevents startup (N5/N6), and half-configured daemons exit at
  startup rather than running degraded (#393/#396 gating).
- Interrupted-transfer semantics: a destination SIGKILL mid-BULK_COPY fails the
  source task; the restarted receiver refuses to truncate the partial receiving
  volume (create_new); the documented operator recovery (remove the partial, re-
  trigger) completes with digest verification (N9).

**Not claimed (§6):** dirty-block transfer under concurrent writers (#394), the
CP-orchestrated `agent migrate_vm` path (fails closed in core-managed mode by
design), multi-host migration, non-local backends.

## 2. Harness

Same deploy shape as M4.4/M4.5 (`deploy.sh --exec`, identity guard pins the
migration-relevant crates/proto between the staged candidate SHA and HEAD). The
scenario adds two standalone stords — deliberately **not** agent-supervised (#385: a
supervisor respawn generates a minimal config that drops `[migration]`) — plus a
throwaway plaintext echo listener for N8:

- **SRC** — own `socket_path`/`runtime_dir` under TEST_DIR, `[migration] enabled`
  with the client identity (`client_cert_path`, `client_key_path`, `ca_cert_path`,
  `dest_server_name`).
- **DST** — own `socket_path`/`runtime_dir`, `[migration] enabled` with the receiver
  fields (`listen_addr = 127.0.0.1:51052`, `server_cert_path`, `server_key_path`,
  `client_ca_path`) — the #390/#393 mTLS TCP receiver listener.

Identities: one "good" CA and per-role leaves (server SAN `localhost`, client leaves
carrying the `clientAuth` EKU — asserted as a precondition), an unrelated CA
(`ca2`) with its own client leaf (N2/N4), an openssl-CA-backdated expired client
leaf (N7, EKU-preserving recipe), and mismatched/malformed material (N5/N6). The
4 GiB volume (1024 × 4 MiB chunks, one repeating patterned block) is sized so
BULK_COPY is observable by 0.3 s status polling and long enough to SIGKILL the
destination mid-copy.

grpcurl is **pinned and verified at runtime**: v1.9.3 downloaded from the GitHub
release, checked against `grpcurl_1.9.3_checksums.txt` (sha256; note the asset is
named `grpcurl_1.9.3_checksums.txt`, not `checksums.txt`) — provisioning record in
`/var/lib/chv/qual/m4.6-artifacts/grpcurl-provisioning.txt`.

## 4. Findings

Three recorded product findings (none fixed in this PR — the campaign rule is:
scenario + evidence only; product changes go through their own PRs), worst first,
plus the harness traps that produced false failures along the way.

### 4.1 #394 (recorded, open) — dirty-block transfer under concurrent writes is unprovable at this layer

The scenario proves the dirty-round *machinery* executes (SRC log:
"starting iterative dirty sync rounds" → "no dirty blocks remaining"; status
converges at `dirtyBlocksRemaining=0`) but with a **quiescent source** — the
scenario's writer is the harness, which stops before the trigger. A
deployment-realistic concurrent-writer leg cannot exist yet: the source bitmap is
only populated by `LocalFileBackend::write_block` (stord-mediated writes), so
neither guest-initiated writes through the CH-held fd nor host-side writes to the
file are tracked — which is exactly issue #394 (silent data loss for concurrent
writes; no post-pause final sweep either). Dirty-block *transfer* is proven at
protocol level only, by the in-repo e2e test
(`crates/chv-stord-core/tests/migration_e2e.rs::dirty_rounds_transfer_concurrent_writes`),
not by this deployment-realistic scenario. The DIRTY_SYNC legs are labeled with
this boundary wherever they pass.

### 4.2 Destination-only (receiver-only) stord is not expressible (recorded)

`load_migration_tls` treats `migration.enabled = true` as gating **both** halves:
the client identity (`client_cert_path`/`client_key_path`/`ca_cert_path`/
`dest_server_name`) is mandatory whenever migration is enabled, even on a stord
that only ever *receives* migrations. Run 1 died on exactly this — the scenario's
DST had only the receiver fields and stord refused to start. The workaround (the
scenario's DST carries a client identity it never uses) is benign but the
configuration surface does not match the deployment reality it names: only
source-only is expressible, destination-only is not. Recorded as a config-model
finding for the spec/owner to decide (a `role`-style key or making the client half
lazy).

### 4.3 mTLS rejection observability (recorded)

Two distinct client-side manifestations of identity rejection:
- **Client-side rejection** (SRC cannot validate DST's cert: N2 wrong CA, N3 wrong
  server name, N8 non-TLS endpoint): the task error is
  `failed to connect to peer with mTLS: transport error` — the underlying rustls
  reason (unknown issuer vs name mismatch vs not-TLS) is **not surfaced**; N2 and
  N3 are indistinguishable from the error alone (the scenario separates them by
  the SRC log's `dest_domain` field and by construction — N2 is Leg P's identity
  with only the CA swapped).
- **Server-side rejection** (DST rejects SRC's client identity: N4 rogue CA, N7
  expired leaf): in TLS 1.3 the SRC's handshake completes before DST processes
  its certificate flight, so the alert races the client's in-flight request and
  the surfaced task error is an **opaque, race-dependent transport-level form** —
  observed as `status: Cancelled, "operation was canceled"` (run 2) and as
  `status: Unknown, "transport error"` (run 3) for the same legs — while the
  **destination logs nothing at all** about the rejected handshake. The scenario
  asserts the disjunction of observed forms plus the fail-closed invariants
  (task FAILED, zero bytes, no receiving volume).

Neither is a correctness defect (fail-closed holds in every case, zero bytes
transferred), but an operator triaging a failed migration cannot tell a wrong-CA
source from an expired leaf from a network fault without reproducing the
handshake out-of-band. Recorded as an observability finding.

### 4.4 Confirmed-correct behaviors worth naming

- **No plaintext path exists** (N1 + N8): a missing TLS config is refused at
  trigger time with an error naming the exact config keys, and an `http://`
  endpoint is force-upgraded to `https://` before dialing (SRC log) — the
  downgrade attempt then fails the TLS handshake against the non-TLS listener.
- **create_new protects partial data** (N9): the restarted receiver refuses to
  truncate an existing partial receiving volume ("refusing to truncate it"),
  turning a blind retry into a loud failure instead of silent data destruction;
  recovery is deterministic and documented (remove the partial, re-trigger).
- **Finalize verifies** (#397): COMPLETED implies the receiver's versioned SHA-256
  digest matched — the harness re-verifies independently at the file level.
- **Interrupted transfers fail loudly** (N9): a destination SIGKILL mid-BULK_COPY
  surfaces at the source as a FAILED task with the h2/transport error, not a hang.

### 4.5 Harness traps (fixed in the scenario; recorded for future legs)

- **CloseVolume returns a bare `Result`** — unlike OpenVolume/TriggerDiskMigration
  which wrap it as `.result`, so `.result.status` parses empty and every close
  "failed" (4 false failures in run 2).
- **tracing writes ANSI escapes between the message text and field values** —
  grep needles must not span message→field boundaries; assert on the clean value
  (e.g. the upgraded `https://…` URL), not `message…field=value`.
- **A SIGKILLed stord leaves its UDS socket file behind** — `test -S` then passes
  vacuously for a restart wait. Always `rm -f` the socket before restarting a
  daemon whose liveness is gated on `test -S` (run 2's N9 restart assert raced).
- **TIME_WAIT sockets read as port-in-use** — a plain `bind()` probe fails on
  TIME_WAIT entries left by closed migration connections; `SO_REUSEADDR` gives
  the intended semantic (an active listener still fails the bind).
- **tonic error text is the contract** — `Status::to_string()` prefixes
  (`status: Unavailable, message: "…"`) and the sender's wrapper text are what
  the RPC exposes; the rustls detail is not chained, and server-side rejection
  is race-dependent between two opaque forms (§4.3). Needles must be chosen
  from observed output (`failed-migrations.jsonl`), not from the TLS layer's
  vocabulary.
- **protojson renders uint64 as strings** (`"0"`, `"4294967296"`) even with
  `-emit-defaults` — compare as strings.
- The M4.5 idiom `wait_for … && qual_pass … || qual_error` double-reports a
  timed-out poll (accounting noise only) — shared, recorded not fixed.

## 5. Layer truths (as-operated, for the record)

- **Migration task state is in-memory** (no cross-restart resume): a restarted
  destination knows nothing of the killed task; the operator re-triggers and gets
  a new migration_id for the same volume+handle.
- **Receiving volume path:** `{DST runtime_dir}/{volume_id}.img`, created via
  create_new — an existing file is a hard refusal, never a truncate.
- **Phase machine as polled:** `BULK_COPY` → `DIRTY_SYNC` (rounds) →
  `PAUSED_FINAL_SYNC` (`needs_vm_pause=true`) → (resume) → `COMPLETED` / `FAILED`.
  DIRTY_SYNC is too transient to poll at 0.3 s on a quiescent loopback source —
  its execution is asserted via the SRC log lines instead.
- **`dest_endpoint` is per-trigger** (RPC field), while the client identity and
  `dest_server_name` are per-daemon config — N8 exploits this to aim a good SRC
  at a plaintext listener without touching its config.
- **The receiver listener re-binds cleanly after SIGKILL** (tonic sets
  SO_REUSEADDR): same identity/config restarts without port conflicts.
- **Session store:** each standalone stord persists sessions in its own
  `stord.db` (runtime_dir); the close-out asserts `SELECT COUNT(*) FROM sessions`
  = 0 after CloseVolume on the scenario source.
