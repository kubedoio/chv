## 1. Baseline and change

- **Baseline SHA:** `7b338cac` (`docs(evidence): M2.1b durable-operation-metadata qualification`).
- **PR:** [kubedoio/chv#259](https://github.com/kubedoio/chv/pull/259)
  `m2.2a-single-effector-runtime` → **merged to main as `d1028097`** (squash, 12 commits).
- **Problem:** the Core journal was durable + scheduled (M2.1), but
  `CloudHypervisorCoreRuntime` executed only the Cloud Hypervisor adapter call and had a
  **latent bug**: its CreateVm arm did `serde_json::from_value::<VmDefinition>(operation.request)`
  on the canonical envelope `{"command":{...},"expected_vm_version":N}`, which always fails
  `VmDefinition`'s `deny_unknown_fields` → **every real CreateVm was rejected as
  InvalidRequest**. The single-effector contract (one durable authority → wired executor →
  one effector → terminal result) did not exist: the only real provider side effects lived in
  legacy reconcile `prepare_vm_resources`/`cleanup_vm_resources`, still driven by the second
  authority that M2.3 gates off.

## 2. Change (as merged)

- **`HostResourceController`** (new, `chv-hypervisor-api/src/resources.rs`): neutral async
  trait for the host side-effect surface — `open_volume`/`attach_volume_to_vm`/
  `detach_volume_from_vm`/`close_volume` (stord) and `ensure_network_topology`/
  `attach_vm_nic`/`detach_vm_nic` (nwd) — with signatures matching the real
  `StordClient`/`NwdClient` shapes and doc-commented pre/post conditions (open MUST be
  followed by attach, then detach+close on success or close-only on failure).
  **Dependency direction:** the trait lives in the low shared crate so the Core runtime
  (`chv-agent-runtime-ch`) consumes it without ever depending on `chv-agent-core`.
- **Shared pure conventions** relocated verbatim from `reconcile.rs` into
  `chv-hypervisor-api`: `vm_runtime_dir`, `bridge_name_for_network` (incl. `default`→`chvbr0`
  and the `br-` prefix/hash logic), plus `nic_id` (= `{vm_id}-{network_id}`, matching
  `legacy_network_attachment_id`), `vm_api_socket` (`{vm_dir}/vm.sock`), `ensure_vm_runtime_dir`
  (0o775 + tolerant chown to group `chv-stord` when root), `DEFAULT_NIC_CIDR = "10.0.0.0/24"`.
  `reconcile.rs` re-exports the relocated fns via `pub use`, so legacy callers are untouched.
- **`AgentResourceController`** (new, `chv-agent-core/src/resources.rs`): production
  `HostResourceController` impl, per-call `StordClient::connect`/`NwdClient::connect` per
  method — matching the existing agent convention (legacy connects per call too); a down
  stord/nwd maps to `RuntimeUnavailable` at execute rather than failing agent startup.
- **`CloudHypervisorCoreRuntime`** (rewritten, `chv-agent-runtime-ch`):
  - **Fixes the latent envelope bug**: parses `operation.request` as the canonical
    `MutationCommand` envelope (`{command, expected_vm_version}`).
  - **CreateVm** = ensure `{runtime_dir}/vms/{vm_id}` (0o775 + chown) → open+attach each
    storage (`storage_ref` IS the stord volume_id; disk `path` = stord `export_path`,
    `id` = `attachment_id`) → ensure topology + attach each nic (`network_ref` IS the nwd
    network_id, nic_id = `{vm}-{network}`; tap = nwd `tap_handle`, mac from attachment) →
    `VmConfig` with `api_socket_path = {runtime_dir}/vms/{vm_id}/vm.sock` →
    `adapter.create_vm`; records an **in-memory** side-effects map (volumes + nics).
  - **Partial-failure unwind**: opened-but-never-attached volumes are `close`-only
    (contract-correct), attached volumes get detach+close, attached nics detach, stray
    `vm_dir` removed best-effort; the original mapped error is returned (cleanup errors
    logged, never masked).
  - **DeleteVm**: `adapter.delete_vm` then **always** drains the tracked map best-effort —
    **even when the hypervisor delete fails** (previous bug stranded open stord/nwd handles);
    the entry is preserved for a later retry when the delete did not succeed, and removed
    after a successful delete. A missing entry (fresh runtime after crash) logs the
    documented NHOS warn and still deletes successfully.
  - **Start/Stop(false)/Reboot** passthrough; **Update/Attach/Detach → `Unsupported`**
    (honest fail-closed, not `Ok(None)` which would falsely report Succeeded).
  - **Error mapping** (ChvError → RuntimeFailure): NotFound→NotFound;
    AlreadyExists/Conflict→Conflict; InvalidArgument/BadRequest→InvalidRequest;
    Backend/NetworkUnavailable→RuntimeUnavailable; else Internal.
- **Path-safety (defense in depth).** `VmDefinition`/`StorageAttachmentRef`/
  `NetworkAttachmentRef` `validate()` now reject `/`, `\`, NUL and exact `.`/`..` in
  `vm.id`/`attachment_id`/`storage_ref`/`network_ref` (authority gate — unsafe ids are never
  journaled; fires at serde `try_from` deserialization too). The runtime re-checks ids and
  canonicalizes `vm_dir` to a **strict descendant** of `{runtime_dir}/vms` (protects
  pre-journaled rows; `canonicalize` resolves symlinks so an internal symlink escape is
  caught).
- **Composition** (`cmd/chv-agent/src/main.rs`, core-managed + core-native) constructs
  `AgentResourceController(stord_socket, nwd_socket)` and passes `(adapter, resources,
  runtime_dir)`.

## 3. Invariants (as implemented and reviewed)

1. **Single effector for Core ops.** Every Core lifecycle mutation that needs host side
   effects flows through this runtime; nothing else mutates the provider for Core ops.
2. **Atomic unwind.** Any create failure that opened volumes/attached nics cleans up exactly
   once (close-only for never-attached); a Failed create is terminal and not re-run, so
   unwind is the only chance to clean up.
3. **Delete never strands controlled handles.** The tracked map is drained on every delete
   outcome; failures are logged; the entry survives for retry when the delete failed; removed
   on success.
4. **Fail-closed.** Update/attach/detach → `Unsupported`; malformed envelope / wrong-command
   kind → `InvalidRequest`; path-unsafe ids rejected before any fs mutation.
5. **Audit/no-overclaim.** The in-memory handle map lost on daemon restart is a documented
   residual with an operator drill (below), not a claimed crash-safe cleanup.
6. **Path containment.** No CreateVm path can mutate outside `{runtime_dir}/vms` even with a
   pre-journaled-hostile row (Layer-A authority gate + Layer-B runtime re-check +
   canonicalization).

## 7. Remaining risks / honest gaps

- **KVM-VERIFIED unproven.** No real cloud-hypervisor/stord/nwd lifecycle has been run
  through the side-effect runtime (M2.5 is the scheduled attempt; if CH/guest install is not
  feasible, this stays **unproven** and is reported as such). The CI KVM smoke job was
  label-gated and `skipping` on this PR.
- **In-memory side-effect map (documented).** Volumes/nics tracked by the runtime are
  memory-only; a daemon crash between open/attach and terminal persistence leaks open stord
  sessions / attached nwd nics. Running→InspectRequired ops are never auto-recovered. Operator
  drill documented: enumerate via `ListVolumeSessions` and close via `CloseVolume` on the
  chv-stord gRPC client surface (and the nwd equivalent); verbose in the spec. Durable handle
  persistence is deferred (M2.2b/M3).
- **Response-lost-after-server-commit window.** If chv-stord commits an open server-side but
  the RPC response is dropped, the runtime sees `RuntimeUnavailable`, unwinds nothing for that
  handle (it never learned it), and only the manual drill covers it. Undetectable without tooling.
- **Core request model gaps (documented).** `customize`-level options are not modeled in the
  Core request: disk size_bytes/seed_from → empty options; cloud-init userdata / hypervisor
  overrides → `None`; per-NIC IP/cidr/gateway → defaults (`DEFAULT_NIC_CIDR`, empty gateway,
  DHCP-style attach without static IP). Legacy VmSpec carries these; parity requires a future
  Core model extension.
- **Topology not torn down.** `ensure_network_topology` (bridge/rules) is *ensure* semantics
  and is not torn down on create failure or delete (matches legacy); only the per-VM nic attach
  is detached.
- **M2.2b/M2.3 pending.** NodeCache is not yet a post-Core projection (M2.2b); the legacy
  `Reconciler` provider-mutation paths are not yet gated off and its `prepare_vm_resources`/
  `cleanup_vm_resources` are not yet deleted (M2.3). Until then the legacy path is a second
  effector **in legacy mode only**; Core-managed modes already route solely through the Core
  runtime. Single-host = MULTI-HOST/FIELD unproven.
