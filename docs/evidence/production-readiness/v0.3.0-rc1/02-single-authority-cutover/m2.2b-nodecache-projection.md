## 1. Baseline and change

- **Baseline SHA:** `e5d82913` (`docs(evidence): M2.2a single-effector Core runtime qualification`).
- **PR:** [kubedoio/chv#260](https://github.com/kubedoio/chv/pull/260)
  `m2.2b-nodecache-projection` → **merged to main as `befa5129`** (squash, 10 commits).
- **Problem:** after M2.2a the Core runtime was the single *provider* effector, but
  **NodeCache was still a second-writer hazard** in core-managed mode: the legacy
  `Reconciler` (TenantReady arm + `prepare_vm_resources`/`cleanup_vm_resources`) and the
  legacy `AgentServer` mutation branches could still write NodeCache fragments and/or
  effect the provider *behind* the Core authority's back. There was no crash-consistent
  rebuild of NodeCache from the Core store, and the canonical request envelope
  (`{"command": …, "expected_vm_version": N}`) existed only as a private copy inside
  `chv-agent-runtime-ch` (`CanonicalEnvelope`) — two sources of truth for the journal
  request shape. M2.2b removes the second writer (projection + gating) and the duplicated
  envelope (shared `CanonicalRequest`).

## 2. Change (as merged)

- **`CanonicalRequest`** (public, `cellhv-core-operations/src/lib.rs`): the canonical
  journal envelope `{"command": MutationCommand, "expected_vm_version": N}` promoted from
  runtime-ch's private `CanonicalEnvelope`, with a public `try_from_value` parser returning
  `Ok(None)` for non-object values. `chv-agent-runtime-ch` now consumes it and its private
  copy is deleted (behavior byte-identical; parser unit tests added). **Single source of
  truth** for the canonical request envelope.
- **`AuthorityHandle::disconnected()`** (`cellhv-core-operations/src/authority_actor.rs`):
  test-support constructor (`#[doc(hidden)]`) that returns a never-connected handle whose
  every call resolves to `Unavailable` — proves Gate-send paths fail promptly without ever
  contacting the actor.
- **NodeCache projection helpers** (`chv-agent-core/src/cache.rs`):
  - `project_vm` maps a Core `VmDefinition` into the **legacy VM-axis `VmSpec` fragment**
    (generation = resource_version, power state, attached volumes/NICs) with
    **legacy-shaped `spec_json`** so NodeCache consumers keep working.
  - `projected_mac` derives a deterministic per-NIC placeholder MAC
    `02:00:00:HH:HH:HH` via FNV-1a over `{vm_id}\0{network_ref}\0{attachment_id}` when the
    attachment carries no `mac_address` — valid `02:00:00` unicast OUI, distinct per NIC
    even for duplicate network refs, and never the empty string.
  - `rebuild_from_core` clears only the **VM axis** (volume/network axes untouched) and
    reprojects every store VM with `core-rebuild` attribution — crash-consistency repair.
  - `remove_vm_state` deletes a VM from NodeCache after a Succeeded delete.
- **`ProjectingCoreRuntime`** (composition layer, `chv-agent-core/src/projection.rs`)
  `impl CoreVmRuntime`: forwards `execute` to the inner runtime and, **only on the
  executor's exact Succeeded path (`inner Ok(None)`)**:
  - `CreateVm` → `project_vm`; `DeleteVm` → `remove_vm_state`; `Start`/`Reboot` → desired
    `Running`; `Stop` → desired `Stopped`; `Update`/`Attach`/`Detach` → no-op.
  - **Cross-checks the durable `entry.operation.vm_id` against the envelope id** — warn +
    skip on mismatch (projection never acts on a wrong VM).
  - **Persists the cache only when `project()` returns true** (i.e., a mutation was
    applied). Parse/projection/save failures are warn + skip; the wrapper **never changes
    the Result** it forwards from the inner runtime.
  - Added dependency on `cellhv-core-executor` for the terminal `Ok(None)` semantics
    (arch-guard-clean, see §4).
- **Startup rebuild wiring** (`cmd/chv-agent/src/main.rs`, `start_core_managed`):
  `NodeCache::rebuild_from_core` runs **BEFORE** `CoreRuntimeOwner::start` and the executor
  poller, so no crash-recovery op can race the rebuild. Uses `activated.service().vms()`.
- **Reconciler provider-mutation gate** (`chv-agent-core/src/reconcile.rs`):
  `provider_mutation` flag (default `true`), `set_provider_mutation_enabled(false)` from
  `start_core_managed`; the TenantReady arm then **skips** `reconcile_networks/volumes/vms`
  (observe/health only, no cache or provider mutation).
- **Complete single-writer RPC enforcement** (`chv-agent-core/src/agent_server.rs`): all
  legacy fragment-writing / provider-effecting RPCs **fail closed** (`unimplemented`) in
  core-managed mode. Authoritative classification of all **40** `AgentServer` handlers
  (round-3-reviewed, every gate verified first-statement / single / mode-conditional):

  | Class | Handlers | Count |
  |---|---|---|
  | **GATED** (fail closed) | `apply_node_desired_state`, `apply_vm_desired_state`, `apply_volume_desired_state`, `apply_network_desired_state`; stord: `resize_volume`, `snapshot_volume`, `restore_volume`, `delete_volume_snapshot`, `clone_volume`; CH live-VM: `pause_vm`, `resume_vm`, `power_button_vm`, `add_disk`, `remove_device`, `add_net`, `resize_disk`, `snapshot_vm`, `restore_snapshot`, `coredump_vm`, `migrate_vm`; nwd: `start_network`, `stop_network`, `restart_network`, `update_overlay`, `send_gratuitous_arp`; pre-existing: `resize_vm`, `attach_volume`, `detach_volume` | **28** |
  | **ROUTED** (core-routed, keep) | `create_vm`, `start_vm`, `stop_vm`, `reboot_vm`, `delete_vm` | 5 |
  | **READ-ONLY** (keep) | `acknowledge_desired_state_version`, `ping_vmm` | 2 |
  | **OPERATOR node-state** (intentionally UNGATED) | `pause_node_scheduling`, `resume_node_scheduling`, `drain_node`, `enter_maintenance`, `exit_maintenance` | 5 |

  Net effect: features Core M1 does not model (snapshot/restore, migration, live device
  hot-plug, storage snapshot/clone) are **unavailable in core-managed and fail loudly**
  rather than acting behind the Core authority.
- **Mode boundaries:** legacy mode is **untouched** (all 40 handlers behave exactly as
  before); CoreNative mode has **no NodeCache** (not wired, documented); core-managed is
  the single-writer/single-effector path described above.

## 3. Invariants (as implemented and reviewed)

1. **Single NodeCache writer in core-managed.** NodeCache is mutated only by (a) the
   post-Succeeded projection and (b) the startup `rebuild_from_core`; the Reconciler
   mutation arms and the 28 gated RPCs cannot write it.
2. **Projection triggers only on terminal Succeeded.** The wrapper projects on the exact
   executor Succeeded path (`Ok(None)`); `Ok(Some(_))`/`Err` never project (conservative).
3. **Projection is best-effort.** Any parse/projection/save failure warns + skips and
   **never changes the executor Result**; a skipped mutation is repaired by the next
   startup rebuild.
4. **Crash consistency.** The cache is persisted only when a mutation was actually applied;
   a crash between side effect and persistence leaves the durable (old) cache — reconciled
   away by the next startup `rebuild_from_core` (safe because reconcile is gated).
5. **Rebuild before poller.** `rebuild_from_core` runs in `start_core_managed` before the
   executor owner starts, so no crash-recovery op can race the rebuild.
6. **Complete single-writer enforcement.** No legacy mutation RPC can run behind the Core
   authority: all 28 gates are first-statement, single, mode-conditional fail-closed.
7. **Projection keyed on durable identity.** The projection keys on
   `entry.operation.vm_id` with a cross-check against the envelope id (warn + skip on
   mismatch), so a malformed/mismatched journal row cannot project a wrong VM.
8. **Audit/no-overclaim.** CoreNative having no NodeCache is documented, not wired; the
   placeholder MAC is a deterministic compatibility value, explicitly not presented as the
   real CH-assigned MAC.

## 7. Remaining risks / honest gaps

- **KVM-VERIFIED unproven.** No real cloud-hypervisor/stord/nwd lifecycle has been run
  through the Core runtime + projection (M2.5 is the scheduled attempt; if CH/guest install
  is not feasible, this stays **unproven** and is reported as such). The CI KVM smoke job
  was label-gated and `skipping` on this PR.
- **Projection is a compatibility view, not full parity (documented).** Power-op updates
  project only `desired_state`; `generation`/`attachments`/`updated_at` are not re-projected
  on Start/Stop/Reboot. The placeholder MAC is deterministic but **not** the real
  CH-assigned MAC. Legacy-modeled-but-Core-unmodeled `customize` options (disk
  size_bytes/seed, cloud-init, static per-NIC IP) still project defaults, as in M2.2a.
- **Malformed-envelope skip is conservatively unreachable in the real path** (create
  re-parses the envelope to execute; power/delete dispatch on `OperationKind`); the
  cross-check is defense-in-depth for hostile/legacy journal rows.
- **Cold first-boot rebuild is best-effort.** If `vms()` errors on first boot, `rebuild_from_core`
  keeps the on-disk cache — safe because reconcile is gated (no second writer can diverge it).
- **`Ok(Some)` not projected (conservative).** A non-Succeeded terminal outcome that still
  returns `Ok(Some(_))` leaves NodeCache un-updated; acceptable for the current executor,
  documented.
- **CoreNative has no NodeCache** (not wired). NodeCache is a legacy-mode/core-managed
  compatibility surface only.
- **M2.3 pending.** The now-gated legacy mutation code is still *present* (barely
  reachable/fail-closed in core-managed, fully live in legacy mode): `prepare_vm_resources` /
  `cleanup_vm_resources`, the Reconciler mutation arms, and the 28 gated RPC bodies are
  deleted in M2.3 once compat no longer needs them.
- **Env-only test failures (documented, non-gating).** 20 tempdir-permission/sandbox
  failures in `chv-agent`/`chv-agent-core`/`chv-agent-runtime-ch`, unchanged on clean main.
- Single-host = MULTI-HOST-VERIFIED / FIELD-QUALIFIED **unproven**.
