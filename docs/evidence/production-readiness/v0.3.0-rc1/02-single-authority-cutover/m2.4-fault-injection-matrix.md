## 2. Problem

Prompt 02 §3 requires deterministic fault points at all five crash windows
with restart/replay behavior proven for every point; §4 requires the
six-scenario concurrency/replay matrix. Before M2.4, four of the five
windows had no deterministic crash-injection idiom usable through the real
composition (accept-commit↔reply, claim↔effect, during-effect,
effect↔projection, effect↔finish); no test anywhere proved
**provider success → crash before finish → restart → resolution → no second
effect** end-to-end; `persist_terminal_operation`'s status+event
transaction had no atomicity proof; there was no dropped-submit-reply
convergence proof and no restart-spanning proof of the version fence or of
control-plane-replay convergence.

## 3. Fault-point machinery (as merged)

One reusable parking wrapper at the `CoreVmRuntime` seam —
`cellhv_core_executor::fault::{FaultRuntime, FaultPoint}` — parks the
executor task at a deterministic crash window; tearing the composition down
at the parked point is the process-death simulation, leaving exactly the
durable state a real crash leaves. **Wrapper position selects the fault
point**:

| Point | Window | Injection | Restart/replay proof |
|---|---|---|---|
| 1 | before durable acceptance | accept-transaction abort (store tests: whole-accept rollback + fresh retry) / lost reply after the accept commit (operations tests) | `stale_acceptance_and_failed_event_roll_back_completely` (rollback + retry-fresh), `dropped_submit_reply_converges_on_replay_across_actor_restart` |
| 2 | claim↔effect | `FaultPoint::BeforeEffect` | `fault_before_effect_never_reexecutes_after_restart_until_resolved` |
| 3 | during effect | `MockCloudHypervisorAdapter::park_create` (volumes opened+attached, CH create parked); failures via `fail_next`/`fail_delete` | `canary_crash_mid_effect_never_repeats_partial_effects` (real composition) |
| 4 | effect↔projection | `AfterEffect` inside the projecting wrapper | `fault_after_effect_before_projection_is_repaired_by_rebuild` |
| 5 | effect/project↔terminal persistence | `AfterEffect` outermost | `fault_after_effect_resolves_without_a_second_effect`, `terminal_persistence_and_event_commit_atomically`, canary flagship |

`FaultRuntime` contracts, all pinned by tests: single park per instance
(structural `parked` flag — `armed_fault_runtime_parks_once_then_passes_
through`), `disarm()` pass-through with `inner_completions` counting
(`disarmed_fault_runtime_is_a_passthrough`), timeout-bounded park awaits
everywhere (fail fast, never hang). Production wiring is byte-identical;
the wrapper is inert unless constructed (the `MockHostResourceController`
precedent: always-compiled pub test affordance, no new dependency edges).

## 4. Concurrency/replay matrix (prompt 02 §4)

| Scenario | Proof |
|---|---|
| identical-concurrent → one accepted op | existing authority barrier tests + `dropped_submit_reply…` post-restart replay convergence |
| idempotency reuse, different content → hard conflict | existing (`replay_returns_original_and_changed_request_conflicts` etc.) |
| restart after provider success → no double effect | **new**: canary flagship + executor P5 (call-log equality + stuck-op `running`+marker decisive assert) |
| stale generation cannot override newer accepted state | **new**: `stale_version_is_rejected_across_journal_restart` + existing adapter/unit proofs |
| ambiguous ownership fails closed for destructive recovery | existing marker gates (reinforced by every fault test's resolution dependency) |
| control-plane restart is not VM identity authority | **new**: `canary_control_plane_restart_is_not_vm_identity_authority` spanning a real node restart (replay converges; conflicting identity rejected) |

- No production behavior change: `FaultRuntime` and the mock's `park_create`
  are inert unless constructed/set; production composition untouched.
- Parking is crash-honest: the torn-down composition leaves exactly the

  through the marker + token + fingerprint fences; no test bypasses them.

## 7. Real-host evidence (honest)

- **CODED + CI-VERIFIED only.** The proofs drive the real composition with
  the real `CloudHypervisorCoreRuntime` — but backed by the mock
  adapter/controller, not real cloud-hypervisor/stord/nwd processes. A real
  SIGKILL at an arbitrary syscall boundary and power loss mid-SQLite-write

  KVM qualification belongs to M2.5.

## 8. Remaining risks (documented, not fixed here)

- Post-restart delete cannot drain the dead instance's side-effect handles
  (in-memory handle map lost — pre-existing documented residual; the
  no-double-effect guarantee comes from the journal fence, which is the
  point of the proofs). The mid-effect canary's crashed create likewise
  never closes its opened volumes; the fresh create re-opens `vol-0`
  (no durable double-count — the mock controller is stateless and the
  durable rows are keyed by VM identity).
- The mid-effect park covers the create lifecycle's volume→hypervisor seam;
  other mid-effect seams (e.g., between NIC attach and create) are not
  separately injected — they share the same journal-side fencing, which is
  what the proofs pin.
- OS-level crash injection (SIGKILL at arbitrary boundaries) remains
  untested (M2.5 / out of scope; `ChildGuard` orphan window covered by
  process.rs tests).
