## 1. Baseline and change

- **Baseline SHA:** `aad07d2a` (`docs(evidence): M2.2b NodeCache projection qualification`).
- **PR:** [kubedoio/chv#261](https://github.com/kubedoio/chv/pull/261)
  `m2.3-remove-second-authority` → **merged to main as `ef1f9330`** (squash, 4 commits).
- **Problem:** after M2.2b, single-authority for core-managed depended on a
  **runtime flag**: `Reconciler::provider_mutation: bool = true` (default) flipped
  to `false` after construction via `set_provider_mutation_enabled(false)`. That
  is a footgun: a second composition site (or a future edit) could construct or
  leave a mutation-capable Reconciler in core-managed, silently re-creating a
  second authority (legacy reconcile `reconcile_networks/volumes/vms` opening
  volumes, attaching NICs, and creating/starting/stopping/deleting VMs behind the
  Core journal). The plan had framed M2.3 as *deleting* these paths, but they are
  **not dead**: legacy mode uses them as its entire VM-lifecycle effector.

## 2. Change (as merged)

- **`Reconciler::mutation: Option<LegacyMutation>`** replaces the bool. The
  mutation-only state is the VM `runtime_dir` (used to stage per-VM dirs during
  provider side effects). There is **no setter** — legacy vs observe-only is fixed
  at construction.
- **`Reconciler::new_legacy(...)`** — the legacy constructor, **renamed from the
  neutral `new`** (14 test call sites updated). It is the **only**
  mutation-capable public constructor; producing one requires an explicit opt-in
  by name. Legacy mode receives exactly the same stord/nwd sockets + runtime dir
  as before, so its behavior is byte-identical.
- **`Reconciler::new_observe_only(...)`** — the core-managed constructor: keeps
  only the shared stord/nwd sockets needed for node-state **health observation**
  (Bootstrapping→…→TenantReady, Failed/Degraded recovery probes are read-only:
  `connect` + `health_probe`/`list_namespace_state`), holds **no mutation-specific
  state**, and has no setter.
- **`require_mutation()`** — private fail-closed guard. `reconcile_networks`,
  `reconcile_volumes`, and `reconcile_vms` now call it as their **first
  statement** (before any socket connect or cache write) and return
  `ChvError::Internal` on an observe-only Reconciler. `reconcile_vms` reads
  `runtime_dir` from the mutation surface.
- **`TenantReady` arm** matches on `&self.mutation`: `Some(_)` → reconcile
  networks/volumes/VMs (legacy); `None` → converge nothing (`(true,true,true)`,
  never counting provider drift as degraded), matching the M2.2b gated behavior.
- **`cmd/chv-agent::main`** composes the Reconciler via an **exhaustive
  `AgentAuthorityMode` match**: `CoreManaged → new_observe_only`,
  `Legacy → new_legacy`, `CoreNative → unreachable!` (CoreNative returns
  `run_core_native(&config)` at `main.rs:397`, strictly before this point). A
  **future mode variant is a compile error**, not a silent fallback to the
  mutation-capable constructor.
- **`vm_runtime` field is private** with a read-only `vm_runtime()` accessor
  (`list`/`get`/`vm_counters` for metrics/reporting). The guarantee is documented
  to rest on construction + gates + the 28 fail-closed `agent_server` handlers —
  not on handle hiding (all `VmRuntime` methods take `&self`).
- **Legacy bodies retained (not deleted)**: `prepare_vm_resources` /
  `cleanup_vm_resources` / `reconcile_one_vm` / `create_one_vm` / `delete_one_vm`
  and the `reconcile_*` arms stay as legacy mode's mutation surface. Core-managed
  cannot reach them structurally (no mutation-only state; first-statement
  fail-closed); legacy mode is fully functional (all 25 reconcile tests pass).
- **Documentation**: `docs/specs/cellhv-core-journal-executor.md` single-writer
  precondition + request-modeling residual rewritten to the structural mechanism
  (removed the now-false "until its M2.3 deletion" promise and the deleted
  `set_provider_mutation_enabled` reference); `projection.rs` module doc and
  `main.rs` comments aligned to "observe-only / no mutation surface" vocabulary.

## 3. Invariants (as implemented and reviewed)

1. **No executable second authority in core-managed.** The Reconciler's provider
   mutation is *un-representable*: no mutation-only state, no setter, first-
   statement fail-closed mutation methods, exhaustive mode match. There is no way
   to construct a core-managed Reconciler that can express provider mutation.
2. **Legacy mode fully functional (unchanged).** `new_legacy` receives the same
   sockets + runtime dir; creation/start/stop/delete and the legacy
   `agent_server` `cleanup_vm_resources` delete path behave identically.
3. **Observe-only keeps observation, never mutation.** Health probes remain;
   `reconcile_*` fail closed at the first statement; the VM axis of NodeCache is
   written only by `rebuild_from_core` (startup) and the projection (post-Core).
4. **Future-proofing.** A new `AgentAuthorityMode` variant is a compile error
   (`CoreNative` arm is `unreachable!` — genuinely unreachable via the early
   return, verified by tracing); the mutation-capable constructor is explicitly
   named `new_legacy`.
5. **No panic in reachable service paths.** The `unreachable!` arm fires only on
   a programming invariant violation (CoreNative reaching composition), never on
   a valid config.
6. **Audit/no-overclaim.** Handles are not hidden (vm_runtime accessor returns
   `&VmRuntime`); the guarantee is stated as construction + gates + 28
   fail-closed handlers.

## 7. Remaining risks / honest gaps

- **KVM-VERIFIED unproven.** No real cloud-hypervisor/stord/nwd lifecycle has
  been run through the Core runtime + projection (M2.5 is the scheduled attempt;
  if CH/guest install is not feasible, this stays **unproven** and is reported as
  such). The CI KVM smoke job was label-gated and `skipping` on this PR.
- **Observe-only recovery arms cannot see a dead Core (pre-existing, documented
  follow-up).** In core-managed, the Reconciler's `Degraded`/`Failed` recovery
  probes only stord/nwd. With a dead Core but healthy daemons, the main loop's
  `derive_node_state` flips TenantReady→Degraded while the Reconciler's recovery
  arm flips it back each tick (state flap + a state-transition event per tick).
  This is **M2.2b behavior, unchanged by M2.3**; a follow-up should feed Core
  journal health into the observe-only recovery arms or have them defer to the
  main-loop derive. Not changed here (out of M2.3 scope, would be a behavior
  change needing its own review).
- **Accessor returns `&VmRuntime` (documented).** All `VmRuntime` methods take
  `&self`, so the handle is callable through the shared reference. This is not a
  regression (the field was `pub` before M2.3 and `AgentServer` exposes the same
  handle publicly); the single-authority guarantee rests on construction +
  first-statement gates + the 28 fail-closed handlers, not on handle hiding.
- **`unreachable!` on `CoreNative`.** Fires only if the early `return
  run_core_native(&config)` is ever refactored away — intentionally loud (a
  `main`-level programming invariant), consistent with fail-loud rather than a
  silent rescue to mutation.
- **Env-only test failures (documented, non-gating).** 6 `cache::tests` +
  1 `chv-agent` bin tempdir-authority permission failures, unchanged on clean
  main.
- **M2.4/M2.5 pending.** Fault-injection + concurrency/replay matrix (M2.4) and
  real-KVM qualification (M2.5) are next.
- Single-host = MULTI-HOST-VERIFIED / FIELD-QUALIFIED **unproven**.
