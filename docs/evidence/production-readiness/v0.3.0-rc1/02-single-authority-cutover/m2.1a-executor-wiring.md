## 1. Baseline and change

- **Baseline SHA:** `02b0fc1f` (`docs(plan): Prompt 02 single-authority cutover plan`).
- **PR:** [kubedoio/chv#257](https://github.com/kubedoio/chv/pull/257)
  `m2.1-executor-journal-poller` → **merged to main as `796ca38c`** (squash).
- **Problem:** the Core journal was durable but *effect-dead*. `OperationService`
  persisted every accepted lifecycle mutation, but `JournalExecutor::scan_ready` —
  the only ingress into the execution scheduler — was never called in production,
  so accepted operations were never claimed, executed, or finished. Core-managed
  mode therefore promised an execution authority it did not deliver, while the
  legacy `Reconciler` remained the only provider effector (two-authority gap the
  adapter spec warns about).

## 2. Change (as merged)

- **Composition root owns the executor.** `CoreRuntimeOwner` (composition root used
  by both core-managed and core-native) spins a background poller task that drives
  `JournalExecutor::scan_ready` on a bounded interval (250 ms production), with:
  - **bounded exponential backoff** (base × 2^n, capped at 2 s);
  - **per-scan timeout** (`CORE_SCAN_TIMEOUT = 5 s`): a wedged authority/store
    becomes a counted scan failure with backoff instead of hanging the poller or
    shutdown;
  - **failure telemetry** — consecutive/total failure counters, surfaced as
    `journal_scan_healthy()` / `journal_scan_failures()`.
- **Bounded, single-authority shutdown.** New `JournalExecutor::shutdown_bounded(budget)`
  (budget `CORE_EXECUTOR_DRAIN_BUDGET = 60 s`): graceful drain; on expiry the
  scheduler task is explicitly **aborted** and awaited, returning
  `ExecutorError::DrainTimedOut`. No executor/poller task can issue claim/finish
  RPCs after the authority actor is gone. Shutdown ordering is preserved:
  listener → stop poller (bounded drain/abort) → authority → join → lease release.
- **Fail-closed drain semantics.** Remaining `Running` ops are `InspectRequired`
  on restart (documented crash semantics); a runtime effect already initiated is
  reconciled via `InspectRequired`, precisely spelled out in the docs.
- **Orphan-window hardening.** `ChildGuard` RAII in the CH adapter closes the
  gap between `spawn()` and registration in the vm process map: an armed guard
  SIGKILLs a cancelled create; disarmed only after the vm-map write lock is
  acquired and immediately before insertion (no await between disarm and insert).
- **Health integration.** `HealthAggregator::update_core_journal(healthy)` folds
  journal health into `derive_node_state`; fed from `owner.journal_scan_healthy()`
  **only** in core-managed. Legacy/native behavior is unchanged (`core_journal`
  unfed ⇒ healthy).
- **Bounded bookkeeping.** `scheduled` is pruned to the still-`Ready` set each
  scan (safe because a claimed op is never returned to `Ready`), so the always-on
  poller does not accumulate every operation ever admitted.
- **Fail-closed config.** Zero-duration poller timings are rejected up front
  (`RuntimeOwnerError::InvalidPollerConfig`), not `debug_assert`ed away.
- **Architecture boundary respected.** The executor crate stays dependency-light
  (no `tracing`); drain-timeout observability moved to the composition layer,
  satisfying `scripts/check-cellhv-core-architecture.py`.

## 3. Invariants (as implemented and reviewed)

1. **Single durable execution authority:** the wired `JournalExecutor` is the only
   producer of claim/finish RPCs; the poller is the only caller of `scan_ready`.
2. **No executor survives the authority:** bounded drain or explicit abort always
   precedes authority shutdown / lease release; emergency `Drop` aborts the poller
   (dropping the inline executor, which aborts its scheduler) before the authority
   handle drops.
3. **Fail-closed on ambiguity:** claimed-but-unfinished ⇒ `Running` ⇒
   `InspectRequired` on restart; abort-of-drain never leaves a silent second
   effector.
4. **Bounded everything:** scan interval (backed off), per-scan timeout, drain
   budget, `scheduled` set, backoff cap — no unbounded loop or set on the live path.
5. **Legacy/native health behavior preserved:** journal health defaults to healthy
   when not surfaced (core-native has no aggregation loop — a documented gap).

## 5. Review cycle

The PR was driven through **5 adversarial subagent review rounds** to finding-clean:

| Round | Verdict | Finding fixed |
|---|---|---|
| 1 | 2 SHOULD | bounded drain (`shutdown_bounded`) + backoff/health signal |
| 2 | 2 SHOULD | per-scan timeout (wedge ⇒ counted failure) + CH orphan-window |
| 3 | 1 SHOULD | vm-map lock acquired before `child.disarm()`; fail-closed zero-duration config |
| 4 | 1 SHOULD | unbounded `scheduled` growth pruned |
| 5 | **APPROVE** (0 BLOCKER/SHOULD) | — |

Round-5 audit confirmed: `accepted → running → terminal` is a strict one-way
state lattice (no revert path), `recv ≺ claim` ordering makes the prune
duplicate-free, and shutdown ordering admits no executor-after-authority window.

## 7. Remaining risks / honest gaps

- **KVM-VERIFIED unproven.** No real cloud-hypervisor guest lifecycle has been run
  through the wired executor (M2.5 is the scheduled attempt; if CH/guest install is
  not feasible, this stays **unproven** and is reported as such).
- **Core-native has no health surfacing** of the journal (no aggregation loop); the
  signal is wired in core-managed only. Documented follow-up.
- **M2.1b deferred.** Durable operation metadata (requester, external op ID,
  request timestamp, legacy generation, migration 0004) is the remaining half of
  M2.1 and is a separate PR.
- **M2.2/M2.3 not started:** `CloudHypervisorCoreRuntime` is not yet the single
  full-side-effect effector; the legacy `Reconciler` provider-mutation paths are
  still gated OFF in core modes only via the core-managed routing, and NodeCache
  is not yet a rebuilt projection. Single-host = MULTI-HOST/FIELD unproven.
