# Verify Release Artifacts

This document explains how to verify the authenticity and integrity of CHV release artifacts.

## What you should download

For every release, the following artifacts are attached to the GitHub Release:

| Artifact | Purpose |
|----------|---------|
| `chv-<VERSION>-linux-amd64.tar.gz` | Release tarball with binaries, UI, and install script |
| `chv-controlplane_*.deb` / `*.rpm` | Control plane package |
| `chv-node_*.deb` / `*.rpm` | Node services package |
| `chvctl_*.deb` / `*.rpm` | CLI package |
| `SHA256SUMS` | SHA-256 checksums for all packages |
| `SHA256SUMS.sig` *(if signing is configured)* | GPG detached signature for SHA256SUMS |
| `SHA256SUMS.cosign.sig` *(if cosign is configured)* | Cosign signature for SHA256SUMS |
| `sbom.spdx.json` | Software Bill of Materials (SPDX format) |
| `sbom.cyclonedx.json` | Software Bill of Materials (CycloneDX format) |

> **Note:** Signing is not yet configured for all releases. If `SHA256SUMS.sig` or `SHA256SUMS.cosign.sig` is absent, you can still verify integrity using SHA-256 checksums.

## 1. Download artifacts

From the [GitHub Releases](https://github.com/chv-project/chv/releases) page, download the artifacts you need. For example:

```bash
VERSION="0.1.0"
RELEASE_URL="https://github.com/chv-project/chv/releases/download/v${VERSION}"

# Download packages and checksums
curl -sLO "${RELEASE_URL}/chv-controlplane_${VERSION}_amd64.deb"
curl -sLO "${RELEASE_URL}/chv-node_${VERSION}_amd64.deb"
curl -sLO "${RELEASE_URL}/chvctl_${VERSION}_amd64.deb"
curl -sLO "${RELEASE_URL}/SHA256SUMS"

# Download signature if available
curl -sLO "${RELEASE_URL}/SHA256SUMS.sig" || true
curl -sLO "${RELEASE_URL}/SHA256SUMS.cosign.sig" || true
```

## 2. Verify SHA-256 checksums

Check that the downloaded files match the checksums:

```bash
sha256sum -c SHA256SUMS
```

Expected output:
```text
chv-controlplane_0.1.0_amd64.deb: OK
chv-node_0.1.0_amd64.deb: OK
chvctl_0.1.0_amd64.deb: OK
```

If any file fails the check, **do not install it**. Re-download from the official release page.

## 3. Verify GPG signatures (if available)

If `SHA256SUMS.sig` is present and the project has published a GPG public key:

```bash
# Import the CHV release signing key (if published)
curl -sL https://chv-project.github.io/chv/CHV-RELEASE-KEY.asc | gpg --import

# Verify the signature
gpg --verify SHA256SUMS.sig SHA256SUMS
```

Expected output:
```text
gpg: Signature made ...
gpg:                using RSA KEY_ID
gpg: Good signature from "CHV Release Signing Key <security@kubedo.io>"
```

## 4. Verify Cosign signatures (if available)

If `SHA256SUMS.cosign.sig` is present and the project uses Sigstore:

```bash
# Install cosign if needed
# https://docs.sigstore.dev/cosign/system_config/installation/

# Verify the signature
cosign verify-blob \
  --certificate-identity-regexp='^https://github.com/chv-project/chv/.github/workflows/release.yml@refs/tags/.*' \
  --certificate-oidc-issuer='https://token.actions.githubusercontent.com' \
  --signature SHA256SUMS.cosign.sig \
  --certificate SHA256SUMS.cosign.crt \
  SHA256SUMS
```

## 5. Verify GitHub artifact attestations

CHV stable and RC releases include build provenance attestations generated by GitHub Actions. You can verify that the artifacts were built by the official CI pipeline.

### Prerequisites

- [GitHub CLI](https://cli.github.com/) (`gh`) version 2.49+
- Logged in to GitHub: `gh auth login`

### Verify an artifact

```bash
# Verify the tarball
gh attestation verify chv-0.1.0-linux-amd64.tar.gz \
  --repo chv-project/chv

# Verify a package
gh attestation verify chv-controlplane_0.1.0_amd64.deb \
  --repo chv-project/chv
```

Expected output:
```text
✓ Verification succeeded!

sha256:ABC123... was attested by:
REPO             PREDICATE_TYPE                  WORKFLOW
chv-project/chv  https://slsa.dev/provenance/v1  .github/workflows/release.yml@refs/tags/v0.1.0
```

This proves the artifact was built from the tagged source by the official release workflow.

## 6. Inspect the SBOM

The Software Bill of Materials (SBOM) lists all dependencies and components included in the release. CHV provides SBOMs in both SPDX and CycloneDX formats.

### View SPDX SBOM

```bash
# Pretty-print the SPDX JSON
jq '.' sbom.spdx.json | less

# Count packages
jq '.packages | length' sbom.spdx.json

# List Rust crates
jq '.packages[] | select(.downloadLocation | contains("crates.io")) | .name' sbom.spdx.json
```

### View CycloneDX SBOM

```bash
# Pretty-print the CycloneDX JSON
jq '.' sbom.cyclonedx.json | less

# List components
jq '.components[].name' sbom.cyclonedx.json
```

### Compare SBOMs

You can compare the SBOM against a known-good baseline or vulnerability database:

```bash
# Using Grype (from Anchore) to scan for vulnerabilities
grype sbom.spdx.json

# Using Trivy to scan the SBOM
trivy sbom --input sbom.spdx.json
```

## 7. What to do if verification fails

| Issue | Action |
|-------|--------|
| SHA256 mismatch | Re-download the artifact. If it still fails, report a security issue. |
| GPG signature invalid | Do not install. The release may be compromised. Report immediately. |
| `gh attestation verify` fails | Ensure you have the latest `gh` CLI. If it still fails, the artifact may not be from the official build. |
| Missing `SHA256SUMS.sig` | Check if this release was configured for signing. Nightly builds may not be signed. |

## Trust model

CHV uses a layered trust model:

1. **SHA-256 checksums** — always available. Verifies file integrity (not authenticity).
2. **GitHub artifact attestations** — available for stable and RC releases. Verifies the artifact was built by the official CI pipeline from the tagged source.
3. **GPG signatures** — available once configured. Verifies the release was approved by a project maintainer.
4. **Cosign signatures** — available once configured. Provides Sigstore-based transparency.

For production use, verify at minimum:
- SHA-256 checksums ✓
- GitHub artifact attestations ✓

Once signing is configured, also verify:
- GPG or Cosign signatures ✓
